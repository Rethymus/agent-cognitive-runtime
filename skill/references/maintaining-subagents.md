# 给后续 Agent 的维护入口

此文件面向未来维护者。用户目标：强模型负责判断，经济型模型负责边界明确的执行；经济型子代理默认 xhigh、允许 max、禁止更低；强模型日常 medium/high，攻坚 xhigh/max。不要把这些偏好误认成所有模型的科学最优配置。

## 修改定位

| 用户想改变什么 | 修改位置 |
|---|---|
| 用新模型替代 Luna/Sol/Astra | policies/model-registry.json 对应能力槽位 |
| 改角色分工、默认 effort、次数预算 | policies/subagent-policy.json，核对用户偏好 |
| 改任务分类条件或新宿主协议 | scripts/subagent_router.py + 测试 |
| 改记忆 | scripts/runtime.py 与 local-runtime.md，不混进路由文件 |
| 更新 Codex 原生角色 | 用 render 重新生成 ~/.codex/agents/acr_*.toml，勿手改生成文件 |

provider/adapter 分开：现阶段实现 Codex 适配器。未来模型仅换 ID 且仍能通过 Codex 调用时，可直接换绑定；其他供应商或新 API 协议需要新增适配器并验证，不能只改 provider 字符串声称完成兼容。

## 模型更新流程

1. 读取当前 registry、policy、用户最新要求和安装回执。先看配置差异，不重写整个系统；保留原有私有模型连接与用户模型选择。
2. 读取官方模型资料并检查宿主实际支持的模型/effort/工具。模型名称、价格、可用性和 effort 支持都属于时效信息。候选模型设为 candidate，不能被角色实际绑定。不能以发布日期更晚作为能力更强的证据。
3. 在工作副本更新能力槽位、日期、revision 和来源。校验用户 effort 下限及角色 capability；不支持原 effort 时给出明确差异，不静默映射到更低档。可增加未来模型信息，但未验证的 supported_efforts 不猜测。
4. 运行配置/路由测试、模型替换性质测试、现有记忆回归测试，再运行少量真实有界任务。检查质量、失败、主/子上下文大小、延迟及可观察成本。没有数据时保留 evaluation_status=not_calibrated。
5. render 生成角色文件并比较 diff；确认 registry/policy 哈希一致。更新默认子代理设置时同时写 model 和 reasoning_effort；不要改主代理模型。
6. 对修改前文件作本地备份，记录新旧哈希和具体理由，然后原子替换。用户已明确请求升级时直接完成已授权修改和验证；不用重复求批准。没有用户维护请求的自主经验仍只能提出 candidate。
7. 用真实宿主或只读配置诊断检查加载。在新任务中做一次指定角色 smoke test。失败则撤回本次文件变更；保留记忆库、删除日志和用户后续修改。不能通过恢复旧库让已遗忘内容复活。

## 评测与可撤销性

保持策略不变仅替换一个能力槽位，以相同输入、验收和预算配对测试。建议先 12 个 smoke 场景（能否运行），再 60 个独立任务的配对评测（能力/成本），分离开发、晋升、隐藏回归集。这些数量为起始建议，不保证统计功效；根据错误率和置信区间追加样本。

比较：单强模型、单经济型高 effort、强主代理+经济型子代理、同模型多代理。报告端到端完成率、严重错误、首次通过率、修复次数、范围违规、P50/P95延迟、整项成功成本、路由误判、上下文传递损失。费用未知时报告 token/调用代理指标并标注费用未知，不能填0。

削减过时的脚手架与角色同样是升级的一部分。不要为新模型机械保留旧模型所需的额外检查、上下文重置或多代理层级；用消融试验验证这些规则是否仍产生收益。

## 已知执行边界

路由器校验自己的输入和输出，不是拦截所有模型调用的代理服务器。原生默认值可以被显式 spawn 覆盖；命名角色也有其配置优先级。每次委派必须检查最终 model/effort。当前工具如果不支持按原生角色名调用，就用 resolve 后的显式参数，不能假装 role 文件自动生效。

自定义角色内 agents.enabled=false 用于禁止再委派，但宿主版本和实时覆盖可能影响行为，仍需调用者遵守深度约束。权限继承自父任务，本次不改变宿主沙箱；写入范围由交接协议约束，任意文件访问的宿主不构成强隔离沙箱。

## v0.3 自适应路由维护入口

维护仓库：https://github.com/Rethymus/agent-cognitive-runtime 。本机安装回执 packages/latest.json 的 source_checkout 指向安装来源；源目录不可用时重新获取仓库。

默认派发入口是 adaptive_router.py；model-registry.json 绑定能力槽位，subagent-policy.json 定义角色，adaptive-routing.json 管理特征、检查点和调用准入。旧 route 仅为兼容工具，不绕过当前预约。更新任一层都保存哈希、对应任务族评测与回滚路径。原生角色现在为 8 个，新增 acr_decision 用于短决策合约。

仓库维护入口为 scripts/manage.py，提供 install、doctor、rollback。安装默认仅复制 Skill；--with-roles 生成原生角色，--activate 注册全局入口。不会改主模型或全局 model 默认值。回执与备份存于 CODEX_HOME/cognitive-runtime/packages，回滚不触碰 state 下的记忆和路由库。

后续训练路由器需按任务族、模型与 effort 保留真实观察；未运行的模型结果是 unknown。仅有被选中模型的反馈存在选择偏差，不能据此认定其他模型一定失败。先采集少量低风险、分层抽样的配对结果，独立留出评估错误降级、无益升级及端到端成本；不使用虚构采样概率做离线策略评估。
