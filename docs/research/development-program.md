# 持续研究与开发流程

本流程供后续维护者和新 Agent 使用。它定义如何让新资料改变可检验的设计，不启动定时任务、不自动调用付费模型、不授予候选发布权限。当前运行时和开启能力以 [实现状态](../implementation-status.md) 为准。

0.3.2 新增 [资料驱动迭代工具](../material-evolution.md)：现在可以创建材料包、验证引用与快照、检查语料指纹划分，并生成维护计划及包内来源变更影响报告。它承接本流程的资料审查步骤；后续模型实验尚未自动执行。

## 入口与文件约定

| 要做的事 | 先读 | 更新的产物 |
|---|---|---|
| 了解已有结论 | [9 月证据审查](evidence-review-2026-09.md) | 不因摘要新颖就重写结论 |
| 增加或反驳一条主张 | [证据映射](evidence-map.json)、[来源目录](sources.json) | 主张的适用范围、反证、来源读取深度 |
| 设计一次模型实验 | [研究协议](../../evals/research-program.json)、[评测说明](../evaluation.md) | 冻结后的实验清单、独立任务、判据 |
| 更换模型 | [模型维护](../maintenance.md)、当前注册表 | 宿主能力核对、配对实验、回滚点 |
| 改 Skill 或预算策略 | [目标晋升协议](../design/protocol-spec.md)、实际实现状态 | 明确变更、测试、版本和回滚说明 |

来源 ID 稳定且不复用；编号缺口不代表论文缺失。原有来源记录的核验日期不随文件更新统一刷新。论文修订需同时记录首次日期、读取版本与该版本日期；无法读取全文时降低 access_level，标明缺失部分，不猜补结果。原有阅读记录保持为历史证据，不冒充本轮完整重读。

`evidence-map.json` 中的 claim_id 是工程主张，source_ids 是支持或限制它的原始资料，experiment_ids 是本项目检验入口。`local_validation=not_run` 表示没有项目实证。`policy_change_authorized_by_evidence=false` 表示文献本身不授权改变运行时；用户明确维护请求按正常更改与验证流程处理。

## 一轮研究的完成条件

1. 指定一个会改变工程决策的问题。例如“有无必要在所有子任务后加一轮强模型审查”，而非泛泛搜索自改进代理。
2. 寻找支持证据、反证和设置不同的结果。优先原论文、正式论文集、官方方法与代码；二手资料只做发现入口。
3. 核对任务、样本、模型、工具、对照、数据划分、标签来源、成本、重复次数和局限。未核对部分写 unknown。
4. 将事实观察与工程推断分开。主张至少写出一个能让它被否定或收窄的结果，以及当前项目是否已测。
5. 在开发集上构造最小可验证案例；冻结正式实验前不能用留出集调 prompt。新模型评测必须冻结实际模型与 effort。
6. 完成既定实验后保存公开决定、环境清单、聚合结果与可分享的验收证据。私人运行数据和凭据留在本地；不存储私有思维链。
7. 若证据支持维护变更，提交最小改动并验证。结果不确定则保留不确定，负结果同样进入证据映射；候选不能自行晋升。

停止扩展阅读的条件：关键决策已有足够方法细节与适用边界，继续搜寻不再改变实验设计。此时优先实施评测基础，而非继续堆砌引用。反之，发现版本差异、标签来源不明或成本遗漏时，应回到原文核验。

## M3 的具体交付顺序

### M3.1：先让一次实验可复查

交付运行清单和回执汇总接口，记录根/子模型、实际 effort、任务与输入哈希、记忆版本、工具权限、OS/shell、依赖版本、资源限制、并发、缓存、超时和失败类型。可获得的原生 usage 附来源，缺失用 null；不反推不存在的订阅计费规则。

验收：使用固定的成功、工具失败、环境失败、取消、缺失 usage 五类回执检查汇总；失败成本不能消失，缺失不能变零。回执接口不能宣称拦截全部宿主调用。这里需要新实现，当前 research-program.json 只是规范。

### M3.2：原创建模任务与可信标签

先做以下 fixture 家族。它们是拟构造案例，不是已运行的 benchmark；不复制论文数据集到 MIT 仓库。

| 家族 | 输入变化 | 明确验收 |
|---|---|---|
| 工具版本纠正 | 旧字段、当前官方字段、新任务与旧项目 | 按当前项目版本调用；纠正不跨版本泛化 |
| 偏好与事实 | 相同问题配无记忆／相关偏好／错误旧事实 | 偏好不能改变客观答案；有效偏好在主观任务中可用 |
| 有界并发修复 | 两个写入者共享 revision | 拒绝陈旧写入，重读后保留合法外部变化 |
| 教师交接 | 抽象建议／具体示例，功能目标相同 | 执行者遵守边界，通过独立验收，无隐藏教师答案 |
| 评审播种缺陷 | 正确产物与单一已知缺陷 | 分别统计漏报、误报、修正后的真实正确性 |
| 环境扰动 | 不可用依赖、超时、资源限制 | 环境失败分类正确，所有成本仍被记录 |
| 评测完整性 | 评分器写入、答案文件访问、超额查询 | 事件被记录，边界由隔离层执行，而非仅有文字规则 |

验收：每项都有 expected outcome 的来源、可以独立运行的环境和 train/calibration/holdout 分配。标签存在争议时进入 adjudication 队列，不将任意强模型意见充作人类金标准。近重复实例按模板和项目簇分组，避免同类答案穿过数据划分。

### M3.3：冻结并执行最小配对实验

先 pilot 检查方差和任务可执行性，再填入正式协议中的 sample_size、noninferiority_margin、serious_error_limit 和 holdout_query_budget。它们当前为 null，表示尚不能宣称正式实验可直接启动。正式运行前固定主要终点、排除规则、停止规则和分析版本，避免按有利结果临时修改标准。

先验证 H07 的记录条件和 H05 的标签，再按需求运行 H01/H02/H03。控制调用总量，不默认对全部任务做完整模型笛卡尔积。校准需要探索数据，但探索也计入同一预算；不可通过新 task_id 绕过限制。

## 指标的分母与解释

| 指标 | 计算与约束 |
|---|---|
| acceptance_rate | 独立判据通过的任务数 / 所有分配任务数；取消、失败按预声明规则保留 |
| serious_error_rate | 出现预定义严重错误的任务数 / 所有分配任务数；同时报告类别和区间 |
| total_cost_per_accepted_task | 所有分配任务的完整成本总和 / 验收通过数；零成功时为 undefined |
| receipt_completeness | 有完整所需用量来源的运行数 / 所有运行数；完整不等于已获得订阅金额 |
| memory_induced_error_rate | 无记忆正确而加记忆错误的配对数 / 无记忆正确的配对数；同时给原始计数 |
| followup_reuse | 在所有需复用证据的后续任务中正确使用且满足判据的比例；另报存储成功条件下比例 |
| negative_transfer_rate | 无资产正确而带资产错误的配对数 / 无资产正确的配对数；区分同类与不适用任务 |
| defect_false_negative_rate | 未被发现的已知缺陷数 / 所有已知缺陷数 |
| false_alarm_rate | 被错误否决的正确产物数 / 所有正确产物数 |
| correct_to_incorrect_revision_rate | 评审前正确而修正后错误数 / 评审前正确数 |
| negative_revision_rate | 相同判据下原答案正确、继续推理后错误的次数 / 原答案正确的可比较次数 |
| routing_error_rate | 对有配对真值的样本，路由违反预冻结质量/风险/成本选择准则的比例；缺反事实时不估算 |

任一分母为零，指标为 undefined，不能填零。延迟按任务墙钟时间报告，保留排队与重试；子任务耗时求和不等于用户等待时间。所有区间按独立任务簇处理，重复运行和同一用户多条记录不能当完全独立样本。

## 持续更新与回滚

新论文的支持不足以直接改阈值；新模型公告也不足以替换注册表。更新包应包含原始能力来源、宿主实际可用值、锚点集比较、旧资产兼容性、预算差异与撤回条件。Student 执行失败可能来自 Teacher 表达过于抽象，应先定位问题，再决定换模型还是换资产。

每轮形成 `问题 → 来源 → 主张 → 实验 → 结果 → 变更` 的引用链。研究文件更新用 Git 追踪；运行时变更附独立版本。被否定的主张保留理由和来源，过期资产标记 deprecation 并失效派生项。回滚代码不恢复用户已遗忘的内容。

自动晋升需要 M6 的独立验证者和发布者；在此之前只有人工发起的维护流程。未来若安排周期研究，应另有明确频率、工作量和通知约定，不能从本流程推导无限持续运行。
