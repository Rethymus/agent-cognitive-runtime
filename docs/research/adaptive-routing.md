# Cognitive Runtime v0.3：可审计的双向路由与预算

核验日期：2026-09-09。此次更新基于已安装 v0.2，新增证据门控、检查点降级与事务调用预算。它是可运行的保守规则版本；尚未训练难度预测器，尚未证明能节省某个百分比的 token，或让 Luna 达到 Sol 的实际完成率。Skill 不改变基础模型权重与能力上限。

## 1. 任务难度应如何衡量

难度不是任务自带的一个固定数字。应关注：在某个任务族、给定上下文和工具条件下，某个“模型 × 推理强度 × Harness”组合满足验收的概率。目标形式是 `P(pass | task family, observed features, model, effort, harness version)`；当前没有足够真实标签，因此不输出伪造的成功概率。

2026 年 ICLR 的 RADAR 将不同模型与推理预算的组合视为不同能力配置，从真实回答矩阵估计题目难度及配置能力。这支持将 effort 与模型一起比较，而非认定大模型永远更适合所有任务。迁移到本机的设计判断是：先保留可解释特征与真实结果，积累配对评测后再校准；本次没有直接复现或训练 RADAR。[RADAR 官方论文页](https://proceedings.iclr.cc/paper_files/paper/2026/hash/b1f7288854d3bd476c17725c2d85967f-Abstract-Conference.html)

| 维度 | 应观察的证据 | 对决策的影响 |
|---|---|---|
| 需求歧义 | 交付物是否明确、要求是否冲突 | 未知先查证；真实冲突需要决策 |
| 依赖关系 | 调用链、数据流、接口影响范围 | 跨组件耦合可能需要整体判断，文件数量不是可靠替代指标 |
| 约束交互 | 性能、兼容性、一致性是否互相牵制 | 多约束权衡交给强模型作有界决策 |
| 方法新颖性 | 是否有已验证先例，先例是否适用于当前版本 | 无先例不等于必然困难，但不能直接认定廉价执行安全可行 |
| 可验证性 | 测试、约束检查、可独立核实的来源 | 确定性验收降低监督成本；“看起来合理”不能替代验收 |
| 风险与可逆性 | 操作后果、恢复方式、授权范围 | 风险独立于推理难度；简单操作也可能后果重大 |
| 失败类型与阶段 | 环境错误、执行失误、推理冲突；决策还是执行 | 修环境不增加模型；决策解决后重新评估执行是否能降级 |

v0.3 使用三态门控：明确可执行、需要有界决策、信息不足。所有廉价执行门槛同时满足才委派 economy；unknown 先做一次有界只读调查或测试。探测无法解决未知时再请求决策，而不是无止境搜索。分类仍可能错误：引用存在不证明引用内容正确，门控只能让判断可追溯，最终还要依靠结果核验和真实任务校准。

例子：批量按已确认映射替换资源路径、运行已有测试，一般符合廉价执行条件；改动跨服务幂等逻辑，即使只有数行也存在约束交互；生产删除命令即使很短，也必须按风险处理；依赖包缺失导致测试没启动，先修环境，不能记成 Luna 推理失败。

## 2. 双向交接如何运行

强主代理发现独立且可验证的执行子任务，交给 Luna/xhigh；自身做剩余架构、研究或验收。经济型主代理遇到复杂决策时，先请求 Sol/high 的短决策合约；确有强审查失败证据时才进入 Astra/xhigh，例外攻坚才考虑 max。强模型回答决策、适用范围、证据、反例、执行步骤和验收条件，不默认接管剩余工作。

当原代理核验决策与执行条件后，设置已验证检查点，把后续明确执行交回经济型。这种阶段划分防止整项任务永久留在升级后的模型。子代理不能再派生子代理；Luna 子代理遇难题向父代理汇报，由父代理使用同一预算派发同级决策代理。

主代理已有合适的强模型时，通常自己完成有界决策，避免另起同级强代理重复理解任务。整个系统只在有真正独立工作时并行；Google Research 2026 的受控实验发现多代理收益受任务并行性影响，严格顺序工作可能因通信开销而退化。这里据此采用有条件委派，不能把实验上的增益数字照搬到本机。[Google Research：Agent 系统何时有效](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)

当前宿主的调用边界：当前主模型和其 effort 不能由此 Skill 自动切换；经济型主代理若完全被顺序难题阻塞、没有其他有用并行工作，会返回 `needs_independent_work_or_host_handoff`。这是尚未实现的宿主交接能力，不应掩饰成自动升级成功。八个原生角色文件已生成并安装；本轮真实调用使用工具显式 model/effort 参数，没有证明宿主逐一加载执行了八个命名角色。

## 3. 如何避免过度升级与额度失控

先通过已有上下文和确定性工具分类，减少专门用于判断难度的模型调用。只给决策代理必要证据和短合约，不转发完整聊天。每项任务使用稳定 ID；不同子任务、重试及新反馈轮次共享该任务的调用预算。

| 起始限制 | 当前值 |
|---|---:|
| 子代理新推理轮次总数 | 4 |
| 其中强模型轮次 | 2 |
| 其中 frontier 轮次 | 1 |
| 其中 max effort 轮次（包括 Luna/max） | 1 |
| 同时在途轮次 | 3 |

这些是可维护的起始参数，不是科学确定的最优值。frontier 计入强模型。账本在调用前事务预约，重复 request_id 不得重复启动；取消、失败与重试不会退还已占次数，因为宿主没有可验证的“完全未产生推理”凭据。新反馈轮次也须预约，不能用 followup 绕开计数。当前任务不会因修改策略而悄悄放大其最初预算。

预算耗尽时保留已验证成果和明确阻碍，不自动把高风险工作强行降给廉价模型。预算控制的目的也不是让强模型比例永远最低；复杂任务增多时强模型比例上升可能合理，应观察任务构成与实际增益。

WISERouter 是 2026-07-26 的预印本，将路由表达为带整体工作负载预算的上下文 bandit，讨论历史反馈和受约束探索。这启发后续建立跨任务预算分配，但本地 v0.3 只实现单任务调用预约，并未实现其学习算法、全局工作负载控制或论文保证。[WISERouter 论文](https://arxiv.org/abs/2607.23765)

当前限制必须分清：经过接口的调用次数可被本地数据库拒绝；整个 Codex 的 token 消耗不能被这个数据库硬性封顶。主模型持续推理、直接绕过接口的调用、输出 token 上限和账户共享额度不受此接口拦截。子代理工具未提供逐次 token 账单，本次 usage_tokens 为 null；`observed_tokens=0` 只是没有已知回执，绝不表示本轮免费或没有使用 token。

如果追求绝对 token/费用上限，后续需要由宿主或统一执行层提供每轮预算、实际用量回执、运行中取消、主/子调用统一准入。账户剩余额度只能作为参考，不能从共享额度变化准确归因单一任务。本次未新增外部 API 或付费代理服务。

成本也须按端到端算：主模型分解与监督 + 子模型执行 + 上下文传递 + 工具等待后的续写 + 返工。即使 Luna 单价较低，xhigh/max 的较长执行也不保证更便宜。保持主代理只推进有用工作，避免重复思考、空转轮询和无收益审查。

## 4. 严格核验应核验什么

父代理核验交付范围与改动、验收结果、证据是否对应当前版本、外部副作用及剩余未知。对关键断言查看原始证据；适合时运行独立测试。不能只信子代理总结，但也不必把子代理已做的每个步骤完整重做一次。复杂决策的监督重点是约束是否满足、反例是否排除、来源是否充分。

模型的 critique 是有用意见，不是独立正确性证明。同一错误可能被多个模型共同接受，重复多数票不必然增加可靠性。确定性评估优先，开放性问题使用盲评或独立标准；核验标准在执行前约定，不能让执行者看到失败后放宽标准。

自学习仍仅保存 candidate 的公开 decision assets：Problem Pattern → Decision → Evidence → Failure Mode → Heuristic → Validation Result。没有独立留出评测与发布器，candidate 不能自动 verified/promoted，不能直接修改 Skill、预算或路由权重。本轮是用户明确请求的维护更新，有安装与回滚回执；不是模型自主晋升经验。

## 5. 如何知道路由真的改善

RouteLLM 用偏好数据训练强弱模型选择器，说明路由可以从真实反馈学习；论文模型组合、偏好分布与本机工作负载不同，不能直接转用其成本收益或认为已校准 Luna/Astra。[RouteLLM 论文](https://arxiv.org/abs/2406.18665)

至少对照：Luna/xhigh 单代理、Luna/max 单代理、Sol/high 单代理、Astra/high 单代理、固定强主代理＋Luna、当前自适应 Harness。原始单代理与 Harness 组应保持工具、输入、验收及预算可比；报告实际配置，不把不同 effort 合并成同一模型标签。

任务族涵盖：局部确定性执行、跨组件修复、多约束架构、开放研究、长任务恢复、环境故障、对抗性模糊需求。先做能否执行的 smoke；再进行分层的真实配对样本。每族约 30 个样本可作为初始检查起点，但不是足够统计功效的承诺；罕见严重错误需要更多样本或专门压力测试。开发集、阈值选择集、隐藏回归集隔离，并按时间/项目划分以减少泄漏。

| 指标 | 定义与解释 |
|---|---|
| 验收完成率 | 同一预先确定标准下完成数 / 尝试数，附样本量和区间 |
| 错误降级率 | 在配对样本中，路由给廉价方案而廉价失败、可用强方案通过的比例；强方案也失败另记 |
| 无益升级率 | 配对样本中，升级没有可检测质量收益但增加成本的比例，结合风险与统计不确定性 |
| 严重错误与越界 | 单独计数，不能被总体平均分掩盖 |
| 成本与延迟 | 包括协调、复核、重试的总用量，成功成本及 P50/P95；未知费用标 unknown |
| 预算执行 | 准入拒绝、重复请求、取消、任务 ID 分裂、绕过接口情况 |
| 未知率与校准 | 未知分类比例、任务分布漂移；有真实概率预测后才算 Brier/ECE 等 |

只观察被选中模型会产生选择偏差：Luna 没被运行，不能记它失败；Sol 没被运行，不能记升级无用。以少量低风险分层配对试验补足反事实证据，控制探索总预算；如果没有真实随机探索与采样概率，不使用 IPS/SNIPS/DR 等方法编造无偏估计。当前 ledger 不是完整评测数据集，另附 eval-record 模板记录真实运行。

以后更换模型，先更新能力槽位、支持档位、来源和复核日期，再用锚点任务做配对评测。未知支持范围不能猜；旧模型的失败记忆和阈值不能自动视为新模型性质。模型、职责、门槛三层分别维护，避免替换模型时改遍代码。
